# 需求澄清结果固化（V1）

## P0 决策摘要

## 1. 目标与范围
- 目标：同时覆盖降投诉、提好评、提升人效、减少漏发。
- 范围：行前 + 行中 + 行后全流程。

## 2. 通知渠道
- 参团成功：短信通知。
- 新文档内容：企业微信群发。
- 主体策略：以系统自动化为主，失败转人工介入。
- 兜底：企业微信建群能力保留（可包含 2+ 管理角色）。

## 3. 触发规则
- 必发节点：时间点相关通知、投诉/情绪不稳定告警。
- 触发来源：天气接口 + 业务标签 + 管理员确认。
- 审核策略：固定模板默认免审核。

## 4. 终端形态
- 本期仅后端。
- 角色以管家为主，支持对司导的必要提示。
- 游客端沿用既有小程序，不重复建设。

## 5. 权限
- 非管家角色默认无业务操作权限。
- 模板创建/编辑、群发/重发/撤回：管理员。
- 关键操作必须写审计日志。

## 6. 系统对接
- 核心数据源：易途 API。
- 行程变更后：自动更新并在群内通知，由客户确认。

## 7. 验收标准
- 发送成功率、漏发率、模板正确率（>=90%）。
- 观察期：上线后一个月，依据反馈持续修正。

## P1 决策摘要
- 模板：支持多版本追溯。
- 运营：支持按季节/线路/人群自动选模板。
- A/B 测试：支持。
- 满意度：表单收集，低分自动触发跟进。
- 报表：按团导出表格，支持异常告警。

## 仍需补充的关键参数（建议尽快确认）
1. 每日早/中/晚固定发送时点（含是否可按团覆盖）。
2. 特殊触发阈值（如降雨量、气温、紫外线等级等）。
3. 情绪识别规则与误报容忍度（NLP 关键词/模型阈值）。
4. UAT 样本量定义（建议至少覆盖 10 条线路、每条 20 团以上）。
