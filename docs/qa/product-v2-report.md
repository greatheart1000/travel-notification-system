## 二、按需求文档补齐的产品能力

### 1. 企业微信群及时提醒
- 定时调度按 `行前 T-3 / T-1`、`行中 07:00 / 12:30 / 20:00`、`行后回访` 执行，时区统一为 `Asia/Shanghai`。
- **同一条群消息只发一次**：原实现按游客循环，群里会有 N 条重复消息；现在按“行程 + 时段 + 场景”去重，直接发到对应企业微信群。
- 没有游客手机号也能发群提醒；群消息不再自动补发短信。
- 新增「提醒游客」：管理员/导游可在行程详情中生成、编辑并发送群提醒；天气预警支持勾选多个旅行团批量发到各自群。
- 未配置群的行程会在「团队执行」页集中标红，点击直接进入该行程「群配置」。

### 2. 管理员看得见每位导游的内容
- 新增「团队执行」页：左侧导游/成员列表，右侧展示：
  - 负责的旅行团；
  - 每条通知的实际内容、发送时间、渠道、发送对象、发送人、成功/失败状态；
  - 负责行程的群配置状态。
- 行程列表新增「负责导游」列；行程详情头部显示负责导游。
- 通知规则页可展开查看每条规则实际发送的模板内容，并显示绑定模板与规则条件。
- 通知实际发送内容写入 `notification_attempts.content`，支持追溯；旧数据会显示“未记录通知内容（历史数据）”。

### 3. AI 自动润色
- 新增 `POST /api/notifications/ai-polish`：
  - 配置 `GLM_API_KEY` 时调用智谱 GLM；
  - 未配置时使用本地安全润色：保留事实、统一语气、补全结尾，不会编造内容。
- 行程详情通知编辑、通知规则模板、群提醒弹窗均可一键「AI 润色 / AI 生成」。
- 群提醒留空时，AI 会结合当日行程、交通、酒店生成提醒；行前行程会生成“行前提醒”，行程中生成“今日提醒”，结束后生成“行程回访”。

### 4. 规则模板与实际发送一致
- 调度器现在优先使用命中规则绑定的模板，而不是重新随机挑选模板；规则页看到的内容就是实际发送内容。
- 默认规则模板按阶段/时段绑定：行前 3 天、行前 1 天、早间、午间、晚间、满意度回访。
- 特殊场景标签支持列表交集匹配，天气预警规则不再被错误的标签条件阻断。

## 二点五、导游优先的工作台与天气 Agent

### 1. 导游登录后的第一屏
- 非管理员登录 `/trips` 后直接进入「我的工作台」，不再先看到管理员式表格。
- 工作台展示：今天要跟进的行程、行前/在途/回访阶段、群配置状态、最近一次通知内容和发送结果。
- 每个行程卡片直接给出动作：「发送行前提醒」「发送今日提醒」「发送回访提醒」或「查看行程」。
- 失败通知、缺群行程在顶部突出提示；移动端卡片式布局。
- 截图：`screenshots/07-guide-workspace.png`。

### 2. AI 情况识别与导游审批
- 新增 `GET /api/trips/{trip_id}/reminder-suggestion`：
  - 自动判断行前、在途、回访、特殊场景、天气预警；
  - 结合目的地和区域知识生成提醒，例如喀纳斯保暖、吐鲁番防晒、塔县高原/边防证、喀什民俗；
  - 返回建议内容、原因、区域提示和 provider。
- 行程「执行流程」顶部显示 AI 建议卡片；导游可「同意并发送」或「修改后发送」，同意后立刻发送到企业微信群。

### 3. 天气应急 Agent
- 当目的地出现天气预警时，Agent 自动生成两类消息：
  - 游客群通知：天气、温度、预警、区域注意事项；
  - 内部协同提醒：车辆防滑/雨具/路线/集合时间/室内备选行程等建议。
- 按天气类型生成不同建议：暴雪、道路结冰、降雨、沙尘、大风、高温、大雾、寒潮。
- 卡片内可切换「游客群通知 / 内部协同提醒」，内部消息可复制给司导/管家，不会误发游客群。
- 截图：`screenshots/08-weather-agent.png`、`screenshots/09-weather-agent-internal.png`。

### 4. 失败通知重发与参团短信
- 团队执行页对失败通知提供「重发到群」，直接复用原文重发。
- 行程游客名单新增「参团成功短信」：仅管理员可操作，仅对已填手机号的游客发送；同一游客重复点击会跳过，不重复扣费。
- 服务类通知仍统一走企业微信群，短信只用于参团成功通知。

### 5. 行程发送计划：早上、中午、晚上、第二天早上
- 每个团在「发送计划」中按完整时间轴排好：
  - 行前 3 天 07:00、行前 1 天 20:00
  - 行中每天 07:00 早间、12:30 午间、20:00 晚间次日预告
  - 行后当天 20:30 回访
- 内容按当天行程、酒店、区域提示、季节模板生成；第二天早间会带上第二天的行程安排。
- 每条消息显示状态：已发送 / 发送失败 / 待发送 / 已错过。
- 导游可以逐条「AI 润色」「修改后发送」「发送到群」，发送后状态回写。
- 截图：`screenshots/12-message-cadence.png`、`screenshots/13-message-plan-top.png`。

### 6. 每团发送模式：自动 / 需确认
- 每个旅行团独立保存 `send_mode`，两种模式：
  - **自动发送**：到达 07:00 / 12:30 / 20:00 等计划时间后，系统直接把群消息发到本团企业微信群。
  - **需我确认**：调度器到点不自动发送，只保留在「发送计划」里，由导游检查、润色或修改后逐条发送。
- 行程「发送计划」顶部提供模式切换；有 `notification:write` 且被分配该团的导游可以自行切换，管理员可切换任意团。
- 切换写入审计日志 `trip_send_mode_updated`；需确认模式被调度器跳过时记录 `auto_notification_held_for_approval`。
- 导游工作台、团队执行、行程计划都会显示当前模式；团队执行页可一眼看到哪些团暂停了自动发送。
- 截图：`screenshots/14-send-mode-approval.png`、`screenshots/15-staff-messages-mobile.png`、`screenshots/18-team-send-mode.png`。

### 7. 分岗位消息：团期负责人 / 旅行管家 / 司机
- 按《新疆旅行四季提示语（分岗位发送版）》拆成三条独立消息线：团期负责人、旅行管家、司机；早间 / 午间各一条，按当前月份自动使用春/夏/秋/冬模板。
- 每条消息独立显示状态、接收方式、接收对象，可单独「AI 润色」「编辑」「单独发送」；发送后状态回写，调度器不会重复发送同一岗位同一时段已手动发送的内容。
- 接收目标支持三种：跟随本团企业微信群、岗位单独企业微信群、岗位短信手机号；在行程「人员配置」中按岗位配置，导游只读、管理员可改。
- 发送走统一的 `NotificationService`，失败会进入重发队列；消息内容、发送人、接收对象写入通知记录，管理员可在「团队执行」追溯。
- 截图：`screenshots/16-staff-messages.png`、`screenshots/17-staff-recipient-config.png`。

## 三、验证结果
- 后端：`229 passed`
- 前端契约测试：`12 passed`
- 前端 `tsc --noEmit`：通过
- 前端生产构建：通过
- Playwright E2E：7 个页面通过（含「团队执行」）
- 导游账号复验：只看到被分配行程；看不到团队执行/分析/账单；可在行程详情使用「提醒游客」；规则页只读。
- 发送模式复验：导游将「吐鲁番火焰山」切换为「需我确认」，刷新后保持；团队执行页显示「需确认发送」，后端 `send_mode=approval`；切换自动发送后恢复。
- 分岗位复验：QA 数据中配置司机短信接收人，导游单独发送司机早间消息成功，状态由「待发送」变为「已发送」，其余岗位保持「待发送」；管理员在人员配置页可看到三种接收方式。
- 真实数据复验：用户管理页显示陈静、赵玥、吴昊然等真实姓名、企业邮箱和手机号；行程列表显示北疆雪境、伊犁冬牧等真实线路，负责导游显示中文姓名；团队执行页按导游展示其负责的行程和通知内容。
- Unslop 复验：页面中已无 “AI / Agent / 温柔信号” 等界面文案，通知模板无 emoji，页面无渐变文字、彩色光晕和装饰圆环。

## 四、说明
- 当前未配置 `GLM_API_KEY`，AI 按钮使用本地润色并在界面明确提示；配置密钥后自动切换为 GLM。
- 通知模板是租户级共用资源；在规则页润色模板会影响所有引用它的规则，界面已提示。
- 需求文档中“仅参团成功通知使用短信”中的参团成功短信属于独立业务事件，本次未新增报名/支付成功触发器；现有服务通知已按企业微信群为主渠道收敛。
