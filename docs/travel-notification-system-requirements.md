# 旅游业务自动化通知与服务协同系统需求说明（V1.1）

- 文档日期：2026-04-12
- 适用项目：`travel-notification-system`
- 需求来源：
  - `管家操作流程(1).docx`
  - `行程执行流程表.xlsx`
  - `需求澄清会问题清单.docx`

## 1. 项目定位

构建一套围绕旅游行程服务的自动化通知与协同系统，覆盖行前、行中、行后全周期，目标是：
- 降低关键节点漏发与服务遗漏。
- 降低投诉率并提升满意度与好评率。
- 让“管家-司导-客服-销售”协同可追踪、可审计、可闭环。
- 在保持服务温度（模板化+个性化）的同时，提升人效。
- 把优秀旅游工作者经验沉淀为可执行流程，形成“数字计调 + 风控官”能力。

## 2. 业务范围

### 2.1 行前（Pre-trip）
- 出发前 3 天：游客联系、航班变更确认、基础温馨提示、行程单发送司导并留档。
- 出发前：酒店/用车/配套物资检查。
- 出发前 1 天：保险核验、司导短信监督、建群、角色介绍、乘机注意事项发送。

### 2.2 行中（In-trip）
- 落地当日：本地景点/美食推荐与通用在地提示。
- 每日固定时段：早/中/晚提醒（季节化模板）。
- 条件触发：雨天、高原、边境、极寒、强紫外线等特殊区域提示。
- 活动触发：骑马、滑雪等专项安全提示。
- 全程协同：游客-司导-旅行社问题协调与状态跟进。

### 2.3 行后（Post-trip）
- 下团即时：欢送词 + 满意度调研。
- 下团后：售后跟进、低分跟进、高品质游客存档与销售反馈。
- 售后末期：群解散通知与正式解散。

## 3. 系统角色与职责

- 系统自动任务：按规则触发通知、重试、记录审计、触发升级。
- 管家：流程主负责人，监督司导执行，处理异常与人工补发。
- 司导：执行现场通知与安全提示落地，反馈执行状态。
- 客服：处理投诉、低分满意度、售后工单。
- 销售：接收高品质游客线索和服务结果反馈。
- 管理员：模板发布审核、权限配置、关键策略调整、全局审计查看。

## 4. 核心能力需求

### 4.1 通知编排与触发引擎
- 支持三类触发：
  - 必发节点（按里程碑时间点）。
  - 固定时段（日内早/中/晚）。
  - 条件触发（天气/区域/活动/人工勾选）。
- 支持团级规则覆盖（同线路不同团可调整发送时间和模板）。
- 支持条件优先级和去重，避免重复或冲突发送。
- 支持行程结构化解析（Excel/标准行程单），识别骑马、滑雪、高原、边境、早起退房、长途赶路等风险标签。
- 对“赶路日”执行强校验：早餐打包、集合时间、用车余量、关键资源准备项必须确认。

### 4.1.1 行程解析与风险预警
- 接入天气与路况数据，按目的地和时段执行异常检测（雨雪、极寒、强风、高温、封路）。
- 命中风险阈值时，自动生成“预警 + 推荐动作”：
  - 例：建议提前发车、采购雨衣、防滑提示、替代景点方案。
- 预警应支持三层响应：
  - 系统自动发送游客提示；
  - 通知管家/计调人工确认；
  - 未处理超时触发管理升级告警。

### 4.2 多渠道发送与兜底
- 支持短信、企业微信/群通知等渠道策略。
- 支持主渠道失败自动补发。
- 支持失败重试、升级告警与人工接管。
- 发送结果必须可回溯（请求、响应、错误码、重试次数）。

### 4.3 模板与内容管理
- 模板分类：行前、日常提醒（早中晚）、天气/区域风险、活动安全、欢送、满意度。
- 模板支持变量（如游客名、天气、次日行程、集合时间）。
- 支持模板版本管理（草稿/发布/历史回溯）。
- 自由编辑模板应支持审核流；固定模板可免审。
- 增加“场景化标签体系”：
  - 按时间：出发前 3 天、出发前 1 天、落地当天、每日早/中/晚、行程结束。
  - 按天气：晴天/雨天/雪天/极寒/高温。
  - 按活动：骑马、滑雪、越野、高原、边境等。
- 变量引擎需支持动态占位符自动填充（如 `{{目的地}}`、`{{最高温}}`、`{{集合时间}}`），并在发送前做缺失字段校验。
- 模板需支持“按团独立配置”：
  - 同一线路不同团必须可配置不同通知内容、不同发送时段、不同安全提示组合。
  - 通知触发与幂等主键应以 `团号(group_code)` 为核心识别字段，避免跨团误发。
  - 平台应支持“团级模板库”与“全局模板库”并存，默认优先命中团级模板。

### 4.4 协同与问题闭环
- 建群/邀请/介绍/任务下发应可状态化跟踪。
- 游客问题应支持分级处理与责任人归属。
- 低满意度或投诉事件自动触发客服跟进。
- 行程变更自动触发通知，并形成“已送达-已确认”闭环。
- 提供导游“任务驱动工作台（Daily Checklist）”：
  - 系统按当日行程自动生成待办清单；
  - 高风险节点（骑马/滑雪等）必须点击“已讲解/已检查”；
  - 若超时未确认，系统自动通知管家并升级告警。
- 支持“一键发送模板消息”与“一键语音播报”能力，减少司导在行程中的输入负担。
- 建群协同需新增明确状态机（用于仪表盘与运营追踪）：
  - `未建群`：尚未开始建群或缺少关键信息。
  - `建群中`：已发起建群流程但未完成成员确认/欢迎消息。
  - `已建群`：群已创建并完成首条欢迎消息发送。
  - 状态变更必须写入审计，并记录责任角色、变更时间与触发来源（系统/人工）。

### 4.5 审计与权限
- 关键操作（发送、重发、撤回、模板变更、群管理、手工干预）必须写审计。
- 按角色和数据范围做权限隔离（按团队/线路/订单）。
- 审计信息至少包含：谁、何时、向谁、发了什么、结果如何。
- 多租户隔离要求：
  - 数据隔离到租户级（订单、游客、模板、发送记录、报表）。
  - 支持白标配置（Logo、欢迎语、品牌签名、落款规则）。
  - 管理者可跨团队查看汇总报表，业务人员仅可访问授权客户数据（联系人脱敏）。
- 对高风险活动通知保留可举证证据：模板版本、发送时间戳、送达状态、游客回执状态。

### 4.6 数据集成
- 对接订单/行程主数据（游客、航班、酒店、保险、线路标签）。
- 对接天气数据用于风险触发。
- 对接渠道网关（短信/IM）并标准化响应码。
- 支持行程版本变更和冲突处理。
- 对接电子签名/确认单能力，用于高风险活动的“已阅读并知晓风险”留痕。
- 支持售后画像标签同步 CRM（高品质客户、亲子客群、投诉风险客群等）。

### 4.7 仪表盘与数据分析增强
- 仪表盘需在“行程状态”之外，增加“建群状态”标识（已建群/建群中/未建群），并支持按状态筛选旅行团。
- 行程状态与颜色编码统一如下：
  - 绿色：进行中（in_progress）
  - 黄色：临期（即将结束，near_end）
  - 红色：已结束（ended）
- 数据分析颗粒度要求：每个旅行团必须具备独立分析看板/数据表（团级事实表），不得仅提供跨团汇总视图。
- 分析图需补充“建群阶段（出发前）”，并与行中/行后阶段做颜色区分，体现运营准备工作量（天气录入、接送机录入、提醒项补录）。
- 运营报表需支持以 `group_code` 作为主过滤维度，联动查看通知触达率、风险提示触发率、建群完成时效。

### 4.8 企业微信分时段推送细则
- 企业微信日常推送必须拆分为早/中/晚三个时段，且内容差异化：
  - 早间：当日出行准备、安全注意事项、天气穿搭建议。
  - 中午：午间补给提示、下午行程节奏提醒、突发天气预警更新。
  - 晚间：次日详细行程卡片（时间轴/集合点/风险点）+ 次日安全预警。
- 晚间推送需包含“次日详细行程界面”入口（可视化卡片），支持游客与管家查看相同版本，减少信息不一致。
- 时段配置支持“全局默认 + 团级覆盖”，并允许按线路季节做模板切换。

## 5. 业务通知矩阵（MVP）

| 阶段 | 节点 | 触发类型 | 核心内容 | 责任角色 |
| --- | --- | --- | --- | --- |
| 行前 | T-3 天 | 必发 | 航班确认、证件/着装/饮食提示、行程单留档 | 管家 + 系统 |
| 行前 | T-1 天 | 必发 | 保险核验、建群、司导交底、乘机提醒 | 管家 + 司导 |
| 行中 | 每日早/中/晚 | 固定时段 | 季节化提醒、安全提示、次日行程预告 | 系统 + 管家 |
| 行中 | 雨天/极寒/高原等 | 条件触发 | 风险提示与行为建议 | 系统 |
| 行中 | 骑马/滑雪 | 条件触发 | 专项安全提示和责任提示 | 系统 + 司导 |
| 行中 | 骑马/滑雪执行前 | 必发 + 强确认 | 护具检查、资质核验、游客告知确认 | 司导 + 管家 |
| 行后 | 下团后 | 必发 | 欢送词、满意度调查、售后入口 | 系统 + 管家 |
| 行后 | 低分评价触发 | 条件触发 | 危机工单创建与客服升级 | 系统 + 客服 |

## 6. 非功能与运行要求

- 可用性：关键通知链路需高可用，失败可重试可补发。
- 时效性：必发节点应保证准时投递。
- 可观测性：成功率、漏发率、重试率、人工介入率可监控。
- 可维护性：规则与模板优先配置化，避免硬编码。
- 安全合规：敏感信息脱敏、最小权限、全量审计。

## 7. 验收指标建议（P0）

- 发送成功率：>= 99.5%
- 关键节点漏发率：< 0.5%
- 模板渲染正确率：>= 95%
- 低分工单创建及时率：>= 99%
- 审计覆盖率：100%
- 高风险任务确认完成率：100%
- 风险通知提前触达率（事故前）：>= 99%

## 8. 分阶段范围

### 8.1 P0（必须）
- 行程导入与解析：读取 Excel 行程并识别高风险节点（如骑马、滑雪、高原、赶路日）。
- 智能定时任务：支持 T-3 天、T-1 天、出发前 3 小时、每日早中晚等自动触发。
- 话术库 + 变量填充：模板化发送、动态变量校验、常用场景快速调用。
- 导游任务台：当日待办 + 高风险强确认 + 超时升级。
- 通知发送闭环：规则触发 + 渠道发送 + 失败兜底 + 审计留痕。
- 行后满意度收集和低分自动跟进。
- 仪表盘新增团级建群状态标识（已建群/建群中/未建群）并支持筛选。
- 企业微信早/中/晚三时段差异化推送（含晚间次日行程可视化卡片）。
- 通知与分析均以团号为核心维度，支持团级独立模板与团级独立数据看板。

### 8.2 P1（建议）
- 模板多版本运营、按季节/线路/人群自动选模板。
- A/B 文案实验。
- 异常告警与运营报表增强。
- 电子签名风险确认单（游客回执）与法务证据包导出。
- 多租户白标配置与细粒度数据脱敏策略完善。

### 8.3 P2（后续）
- AI 自动生成提示文案。
- 游客画像驱动个性化提醒。
- 多目的地复制与多触达渠道扩展。
- 客户资产运营闭环：自动标签、复购预测、精准营销联动。

## 10. 待确认决策（来自澄清清单，开发前需定稿）

### P0
- 各通知类型的主渠道与兜底渠道矩阵。
- 每日早/中/晚具体发送时间，以及是否允许按团覆盖。
- 发送失败策略（重试次数、升级时点、人工接管 SLA）。
- 条件触发阈值来源（天气接口字段、阈值、人工覆盖规则）。
- 模板审核边界（哪些免审、哪些必须审批）。
- 高风险任务“强确认”口径（哪些项目强制确认、超时多久升级、谁有豁免权）。
- 电子回执法律效力路径（短信链接/小程序签署/线下补录）及取证规范。
- “临期（near_end）”的时间口径（例如距结束 24h / 48h）与颜色展示规则细节。
- 建群状态从“建群中”迁移到“已建群”的判定条件（成员数量阈值、欢迎消息是否必需）。
- 团级模板覆盖优先级规则（团级 > 线路级 > 全局）是否允许运营临时越权。

- 满意度低分阈值与工单规则。
- 核心报表口径和刷新频率。

### P2
- AI 文案生成与个性化策略。
- 多平台扩展（抖音、快手、小红书私信等）。
